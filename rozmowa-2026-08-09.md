## 3. "Najpierw powtórzmy wczorajszy kod SQLite"

Ty: *"wolałbym pierw powtórzyc to co było wczoraj ten kod zwiazany z sqlite i jak wsztk orozumiem przesc do edycji"*

Powtórka wszystkich 3 bloków SQLite spiętych metaforą **"ta sama piosenka"**:

```
1. Otwórz połączenie   →  using (SqliteConnection ...) { connection.Open();
2. Przygotuj polecenie →  SqliteCommand command = connection.CreateCommand(); command.CommandText = "...";
3. Wykonaj             →  command.Execute...();
```

- **Blok 1 (góra):** connection string = "adres pliku bazy"; `using` = automatyczne zamykanie; `CREATE TABLE IF NOT EXISTS` = "utwórz, chyba że już jest" (działa przy każdym starcie); kolumny: Id (PRIMARY KEY AUTOINCREMENT = baza sama nadaje numerek), Nazwa TEXT NOT NULL, Ilosc INTEGER, Cena REAL.
- **Blok 2 (INSERT):** dziury `@nazwa`/`@ilosc`/`@cena` + `AddWithValue` = wypełnienie formularza; nazwa dziury w SQL i przy AddWithValue musi być ta sama.
- **Blok 3 (SELECT):** jak wyżej.

## 5. "Gdzie jest jakiś exit?" — klamra `}` to exit

Ty: *"gdzie jest jakieś exit ? nie rozumiem nadal tej linijki"*

`using (...)` nie ma jawnego zamknięcia — **zamykająca klamra `}` jest wyjściem**. Analogia drzwi automatycznych: `Open()` = drzwi się otwierają, robota w środku, klamra `}` = próg — drzwi zatrzaskują się same. W kodzie NIE MA żadnego `Close()`.

## 6. Pisanie kodu — opcja 4 (usuwanie), krok 1

Wybraliśmy **usuwanie** jako pierwszą migrację (zamiast edycji): prościej, a uczy `WHERE`, którego edycja też potrzebuje.

Kod wpisany przez Ciebie (pierwsza połowa — lista z bazy):

```csharp
command.CommandText = "SELECT Id, Nazwa, Ilosc, Cena FROM Przedmioty";
SqliteDataReader reader = command.ExecuteReader();
List<int> idy = new List<int>();        // parking na numery Id
List<string> nazwy = new List<string>(); // parking na nazwy
int numer = 1;
while (reader.Read())
{
    idy.Add(Convert.ToInt32(reader["Id"]));
    nazwy.Add(Convert.ToString(reader["Nazwa"]));
    Console.WriteLine($"{numer}. {reader["Nazwa"]} | {reader["Ilosc"]} szt. | {reader["Cena"]} zł");
    numer++;
}
if (idy.Count == 0)
{
    Console.WriteLine("📭 Magazyn jest pusty, nie ma czego usuwać.");
}
```

Nowe rzeczy: kolumna `Id` w SELECT, **parkingi** `idy`/`nazwy` (numer na ekranie = `idy[i]` = `nazwy[i]`), `Convert.ToInt32(reader["Id"])` (reader oddaje "bez typu" → zamiana na liczbę).

### Błąd: brakująca klamra
Kod się nie kompilował — **brakowało jednej `}`** (zamknięcia bloku `using`). Wytłumaczone jako pudełka w pudełkach: gałąź opcji 4 → `using` → `if` — każde pudełko potrzebuje własnego wieka. Poprawione przez Ciebie samodzielnie.

### Warning CS8604 → naprawa `?? ""`
Kompilator ostrzegał: *"Convert.ToString może zwrócić pusty tekst"*. Naprawa (wzorzec znany z `ReadLine()`):

```csharp
nazwy.Add(Convert.ToString(reader["Nazwa"]) ?? "");
```

`?? ""` = "a gdyby jednak wyszło puste — wstaw pusty tekst". Kompilator przestaje marudzić.

## 10. Pułapki techniczne przy migracji opcji 3 i 5

Omówione dwa problemy, które wyjdą przy pisaniu kodu — zapisane w planie `nauka-dzien-6.md`, tu wyjaśnione "dlaczego":

### SUM i typy (opcja 5)

SQLite nie ma `decimal` — typ `REAL` w SQL to `double` w C#. `SELECT SUM(Ilosc * Cena)` zwraca `double`, a Ty potrzebujesz `decimal` (bo `Item.Price` to `decimal`). Nie możesz zrobić `(decimal)reader[0]` — rzutowanie `double → decimal` nie działa wprost i dostaniesz `InvalidCastException`. Potrzebujesz `Convert.ToDecimal(reader[0])` — **ten sam wzorzec Convert co przy `Convert.ToInt32(reader["Id"])`**, tylko inna metoda.

Dodatkowo: pusta tabela → `SUM` = `NULL`, reader odda `DBNull`. `Convert.ToDecimal(DBNull)` → wyjątek. Trzeba przed czytaniem sprawdzić `reader.IsDBNull(0)` (nowa metoda readera — analogia: zapytać "czy komórka jest pusta?" zanim weźmiesz jej wartość).

### UPDATE z domyślnymi (opcja 3)

Problem: user może nic nie wpisać (Enter = "zostaw bez zmian"), ale `UPDATE` musi dostać JAKĄŚ wartość dla każdej kolumny w `SET`. Rozwiązanie (wariant A): przed edycją robisz drugi SELECT — `SELECT Nazwa, Ilosc, Cena FROM Przedmioty WHERE Id = @id` — pobierasz aktualny stan wiersza, wyświetlasz go w promptach, a jeśli user nic nie wpisał, do UPDATE wstawiasz wartość z bazy. Jeden pełny UPDATE na końcu (wszystkie kolumny).

Alternatywa B (budowanie UPDATE dynamicznie tylko ze zmienionych kolumn) — bardziej "poprawna", ale na tym etapie więcej ruchomych części, zostawiamy na później.

### Backspace na liczbach

Decyzja: wyrzucić edytor `ConsoleKeyInfo` dla ilości i ceny, zastąpić zwykłym `ReadLine()` + `TryParse` w pętli (wzorzec już użyty w 4 miejscach). Backspace zostaje tylko dla tekstu (nazwa), gdzie ma sens — nie trzeba filtrować cyfr na żywo.
